# Пример заполненного PRD

Собран из примеров лендинга https://prd-for-agents.vercel.app. Используй как ориентир по объему и уровню конкретики.

```markdown
# PRD: Трекер задач с AI-разбиением

## Контекст

Я часто записываю задачи в разных местах (Telegram, заметки) и теряю их. Хочу простой инструмент, где можно хранить задачи на сегодня.

## Цель v1

Понять, буду ли я пользоваться трекером неделю.

## Пользователь

Один пользователь: я. Использую на ноутбуке утром и вечером.

## Основной сценарий

Пользователь открывает приложение → добавляет задачу → задает дедлайн → просит AI разбить задачу → принимает предложенные подзадачи → видит задачу с подзадачами в списке.

## Функциональные требования

- Пользователь может создать, редактировать, удалить задачу и отметить ее выполненной.
- У задачи есть название, статус и дедлайн.
- Добавление новой задачи занимает не больше двух действий после открытия.
- Основная кнопка добавления видна на первом экране.
- После создания задача сразу появляется в списке.
- По кнопке AI предлагает 3 подзадачи; пользователь может принять их или отклонить.

## Нефункциональные требования

- Запускается локально одной командой.
- Данные хранятся локально.
- Не добавлять backend без необходимости.
- Если есть выбор между простым и масштабируемым, выбрать простое.

## Не входит в v1

- Регистрация и авторизация
- Оплаты
- Командная работа
- Push-уведомления
- Аналитика
- Календарь

## Критерии готовности

- README есть, проект запускается по нему.
- Основной сценарий проходит вручную от начала до конца.
- Задачи сохраняются после перезапуска.
- В консоли нет ошибок в основном сценарии.

## Вопросы и риски

- Какой AI API использовать? Пока не решено.
- Что делать, если AI вернет плохие или пустые подзадачи?
- Не станет ли архитектура слишком сложной из-за AI-функции?
```
